# 3D可视化、无人机与图形渲染

来源：[[豆包/raw/编程与技术/3D可视化、无人机与图形渲染]]

> 这组对话围绕一条主线：基于 Three.js 的 3D 场景与无人机自动化巡检系统的技术与项目经验提炼（措辞打磨 + 算法原理）。内容包括大场景加载优化、材质与着色器原理、高程图切分、无人机通信方式，以及巡检系统的摄像头接入与数据可视化集成。

## 核心要点
- Three.js 场景编辑器二次开发：以 three.js editor 为基础封装指定场景组件、导入并解析 geojson 到 3D 场景、用 postMessage 实现 3D 场景与网页的安全通信、重写物体材质判断方式让单面材质也能显示反射、用 GLSL 重写反射材质 shader。
- 碰撞检测与渲染优化：用八叉树（Octree）对摄像头范围内物体做碰撞检测；并行拉取巷道场景物体信息 + 大尺寸物体渐进式加载；用 Web Worker 承载 UI 渲染进程实现加载进度条。
- 大场景预加载四类手段：① 模型格式（GLTF/GLB 二进制打包、Draco 压缩几何与点云，可减 50%–80%）；② 加载器（渐进式加载器、Promise.all 并行加载、事件驱动加载队列）；③ 缓存（浏览器缓存头、应用内存缓存）；④ 场景优化（场景分割、基于八叉树/BSP 树的可见性剔除）。
- 渐进式加载的两条实现路径：基于 LOD 分层（`THREE.LOD` 按距离切换低/中/高模）与纹理分块加载（先加载视角中心 9 块，再补其余）。
- 高程图（DEM）切分五类算法：规则格网（简单均匀地形）、不规则格网（复杂地形、自适应）、等高线（保留地貌特征）、区域生长（高程连续、对噪声敏感）、四叉树（大规模数据、有效减量）。
- 无人机通信：控制指令属无线通信，分射频（2.4/5.8GHz，消费级主流）、卫星（超远距离、高延迟）、蜂窝（4G/5G，城市低空）；"每次只传单个控制指令再回传状态"是请求-响应模型（TCP 保证可靠），MQTT 则是发布/订阅、异步多对多，二者本质不同。
- 单播 vs 广播：状态包单播安全性高、针对性强（测绘、军事侦察），但需为每个接收者建链路、维护复杂；广播高效简单（应急救援、集群编队初始发现），但易被窃听且可能拥塞。
- 巡检系统集成链路：go-sip 信令把不同厂商摄像头注册进流媒体服务，DeepStream 做硬件加速解码，GB28181 接入，AI 识别告警同步上图；cesiumLab 切分卫星图与高程图瓦片、按经纬度加载可视区域；MQTT 串联无人机—网页—后台；飞行日志合并相似数据、提取关键航线节点提信息熵后定时生成报表，并做大屏可视化。
- 材质实现原理：MeshBasicMaterial 不受光照；MeshLambertMaterial 考虑环境光 + 漫反射；MeshPhongMaterial 增加高光（shininess）；MeshPhysicalMaterial 引入 metalness / roughness 更接近真实物理。材质底层由顶点着色器（顶点位置、法线）与片元着色器（像素颜色）共同实现。

## 值得回看的问答
- **three.js 中大的场景文件预先加载有什么好方式优化？并行加载、渐进式加载器的实现方式**：格式（GLTF/GLB、Draco）+ 缓存 + 场景分割/可见性剔除；并行加载用 Promise.all 或自定义加载队列，渐进式加载用 `THREE.LOD` 分层或纹理分块按视角优先级加载。
- **无人机控制指令的传输属于什么方式？MQTT 是基于该方式实现的吗？**：射频、卫星、蜂窝三种无线方式；"单指令 + 回传状态"是一问一答的请求-响应（TCP），MQTT 是发布者—Broker—订阅者的发布/订阅模式，异步、发布者不等响应。
- **无人机状态包收发采用广播还是单播？**：单播安全性高、针对性强但资源消耗与维护成本高；广播高效、实现简单但安全性低、多机同区可能拥塞——救援场景与集群初始发现适合广播。
- **常用的高程图切分算法**：规则格网、不规则格网、等高线、区域生长、四叉树五种，选择依据是地形复杂度、是否需要保留地貌特征与数据规模。
- **three 材质实现原理**：四类材质对应不同光照模型（无光照 → 漫反射 → 高光 → 物理），以及材质与顶点/片元着色器的绑定关系；复杂效果需自定义 shader。
- **场景编辑器开发 / 监控告警识别 / 无人机自动化巡检系统是一套包含什么的系统**：three.js editor + geojson + postMessage 的编辑器方案；go-sip + DeepStream + GB28181 的摄像头接入与告警上图链路；巡检系统由 AI 图像识别、飞行控制、私有三维地图影像服务、摄像头接入服务四大块组成。
