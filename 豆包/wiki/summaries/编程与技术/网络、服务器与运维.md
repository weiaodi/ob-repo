# 网络、服务器与运维

来源：[[豆包/raw/编程与技术/网络、服务器与运维]]

> 这组对话把网络基础（IP 分配、DNS 解析、OSI 七层、代理）与线上排障（502、接口超时、HSTS、whistle tunnel）放在一起，并延伸到运维基础架构（SRE、Docker/Podman、NAS）与安全事件处置（挖矿木马、CA 证书中间人）。

## 核心要点
- 对外只暴露接口而不暴露服务器 IP 的三种做法：域名 + DNS 解析、部署 API 网关（附带鉴权/限流/缓存）、反向代理（可配置多后端做负载均衡）；固定 IP 更容易被持续攻击、不利于迁移，暴露 IP 会招来端口扫描、SQL 注入、恶意爬虫与物理位置泄露。
- DNS 解析全链路：浏览器缓存 → 本地 DNS → 根 DNS → 顶级域（TLD）→ 权威 DNS 返回映射。准确性靠可靠 DNS 服务商与合理 TTL（企业官网可 24–48h，更新频繁的站点 1–2h），安全性靠 DNSSEC 数字签名与防范 DNS 劫持/缓存中毒。
- 手机 IP 由基站 IP 池和运营商负载均衡策略动态分配，经常变化是正常的；对账号体系类业务与网速基本无影响，但长连接（实时视频会议、持续上传）可能短暂断开，动态 IP 反而提高 DDoS 攻击难度。
- Cloudflare 502 Bad Gateway = CF 节点连不上源站或源站返回非法数据。排查顺序：判断全站故障还是单接口故障 → 直连源站 IP 绕过 CF → 查后端进程/端口 → 防火墙是否放行 CF IP 段 → 核对 DNS 记录与 SSL 模式（灵活/完全/严格）→ 查接口超时（CF 默认 100s，最高可设 600s）。
- 历史会话接口偶发超时 502 的归因链：重启只能清锁与僵死线程、解决不了 SQL 慢与数据量大的根因 → 直连源站区分前后端 → 看慢查询日志、统计表数据量、检查索引（含索引失效：`like %xxx%`、函数运算、隐式类型转换）→ 检查是否全量查询、缺少分页与时间过滤 → 归档冷数据、补索引、强制分页、热点数据加 Redis 缓存、微服务加熔断降级。
- SRE 基础架构五大组成：监控与告警、自动化部署与配置管理、服务可靠性设计（冗余容错、故障转移与恢复）、性能优化机制（性能测试、容量规划）、日志与数据管理（日志分析、数据备份恢复）；系统职责是可靠性保障、性能优化、运维效率提升、成本管理与业务支持。
- OSI 七层由下到上：物理层、数据链路层、网络层（IP 路由）、传输层（TCP 可靠面向连接 / UDP 不可靠无连接）、会话层、表示层（加密压缩格式转换）、应用层（HTTP/SMTP/FTP）；提问中的"接口层"不是标准层次。
- 常见故障速查：HSTS 会强制后续请求走 HTTPS，证书或 443 被封时页面报错且无法回退 HTTP（需清 HSTS 记录）；whistle 只看得到 tunnel 通常是根证书未安装信任；Podman Machine 创建失败集中在虚拟化未开启、国内网络拉 Fedora CoreOS 失败、旧配置残留、资源不足（默认 2C/2G/10G）、端口占用、版本混装。
- 服务器安全事件：Suspicious:MaliciousProcess:serious 要区分真中毒（Temp/Downloads 路径、无窗口、外联、自启动）与开发机误报（自写 exe、调试程序、端口监听）；已被挖矿木马（dhpcd）入侵时关机只是止血，木马与 SSH 后门仍在磁盘，测试机最优路线是关机 → 重装系统 → 加固安全组；手机上的"HTTPS 流量可能被监控"弹窗来自自己装的抓包 CA 根证书，不等于被监控，但来路不明的证书会泄露账号密码。

## 值得回看的问答
- **正常如何对外暴露接口而不是 ip 呢？第一种（域名）的解析过程是怎样的？**：域名 + DNS、API 网关、反向代理三种；解析过程是从浏览器缓存逐级问到权威 DNS 再返回 IP，用户全程只见域名。
- **502 Bad Gateway（Cloudflare）是什么问题？这个接口是超时挂了是什么情况？**：CF 只是中间人，502 说明 CF 到源站这一段挂了；超时类多为全量查询历史数据 + 无索引/无分页，触发 CF 100s 上限。
- **这是一个关于历史会话的接口，服务没什么问题，我应该如何排查？我首先想到重启服务但重启不行**：五步排查法（重启 → 直连源站 → 慢 SQL/数据量/索引 → 是否缺分页与时间过滤 → 资源兜底），并给出"归档旧数据应急 + 分页、索引、冷热分离根治"的方案。
- **sre 基础架构是什么？sre 系统主要干嘛的？**：五大组成模块 + 四项核心职责（可靠性、性能、运维效率、成本），并强调故障复盘与容量规划。
- **我的 podman 虚拟机一直创建不成功，是为什么？**：七类原因按优先级排列；M 系列 Mac 优先使用 applehv 驱动，不要混用 brew 与官网安装包。
- **Suspicious:MaliciousProcess:serious 什么问题？服务器关机了可以吗？**：先区分真中毒与误报（看进程路径与行为）；关机=止血不能治病，云上测试机应重置系统盘/重装后加固再用。
