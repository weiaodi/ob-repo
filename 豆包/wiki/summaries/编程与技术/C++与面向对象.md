# C++与面向对象

> 这组对话是 C++ 面向对象与底层机制的连续追问：从 `cout`/自增的表达式求值、交换函数、圆类练习开始，逐步深入到析构函数陷阱、拷贝构造、运算符重载、虚函数表、lambda 闭包、协程实现、对象内存布局（字节数计算、内存对齐）等。大量问题来自课程作业与实验（含类继承的字节数与访问权限分析）。

## 核心要点
- 静态成员函数属于类而非对象，没有 `this` 指针，因此不能访问非静态成员变量和成员函数。
- 析构函数的典型坑：new 未 delete 导致内存泄漏；资源提前释放留下悬空指针；析构函数中抛异常会使栈展开过程进入不确定状态。
- 虚函数表（vtable）是函数指针数组，存放在只读数据段；含虚函数的对象内存头部存 vptr，通过对象实际类型查表实现运行时多态（动态绑定）。
- 派生类的虚函数表继承基类：重写则指针改指派生类实现，新增虚函数则追加，基类表不受影响。
- 运算符重载可写成成员函数或全局/友元函数；风险是行为违反直觉、多个重载造成二义性、与内置类型语义不一致。
- C++ 有类闭包能力但表达方式是 lambda：支持值捕获 `[x]`、引用捕获 `[&x]`、混合捕获 `[=, &y]`；引用捕获局部变量在生命周期结束后使用会出错。
- C++ 标准不允许在函数内定义函数，只能用 lambda、类成员函数或命名空间 + 静态函数模拟。
- 协程两条路线：Boost.Coroutine 通过保存/恢复执行上下文（寄存器、栈指针）实现；C++20 原生支持 `co_await`/`co_yield`/`co_return`，由编译器生成 promise_type 与协程句柄。
- 对象大小 = 各成员变量大小之和，且要考虑内存对齐与虚表指针（64 位通常 8 字节）；`std::string` 的实际大小与实现相关，不能凭记忆给确定值。
- 继承体系中的构造/析构顺序：先基类构造、再派生类构造；析构顺序完全相反（先派生类、再基类）。
- 常成员函数（函数末尾加 `const`）承诺不修改对象数据成员；友元函数不是成员函数但可访问类的私有/保护成员；模板让函数/类适用于多种类型。
- 基类 `protected` 成员在派生类内部可访问，在类外不可直接访问。

## 值得回看的问答
- **c++中析构函数容易产生的问题**：内存泄漏（动态分配未释放）、悬空指针（资源被提前释放后仍被引用）、异常安全问题（析构抛异常导致程序状态不确定）。
- **虚函数表**：本质是函数指针数组，存放于 .rodata；对象内存头部有 vptr 指向本类虚表，基类指针调用虚函数时按对象实际类型查表，从而调用到派生类实现。
- **c++中的闭包存在吗？**：存在等价物——lambda 捕获外部变量即闭包；但它与 JS 等语言的闭包有差别，特别是引用捕获要留意变量生命周期，且 C++ 不支持真正的函数嵌套。
- **c++中协程的实现方式**：早期用 Boost.Coroutine 保存/恢复执行上下文实现暂停与恢复；C++20 引入 `co_await`/`co_yield`/`co_return` 原生协程。
- **house类和office类的对象分别占有多少个字节，怎么计算出来的？**：等于成员变量大小之和（含继承自基类的成员），并要考虑内存对齐与可能的虚表指针，`string` 大小依实现而定。
- **继承类中，构造和析构的调用属性**：构造函数先调用基类再调用派生类，析构函数顺序完全相反（先派生类后基类）。
