# 前端框架核心概念

> 这个专题解决「前端面试里那些会被连追 2~4 层的题，背后的机制到底是同一条还是几条」。
> 依据材料是 3 组对话：一组 JavaScript 语言与手写实现、一组 Vue/React 框架机制对比、一组浏览器渲染与前端工程。
> 内容都以对话时点的机制解释为准，各家框架版本行为可能变化，需核验。

## 框架

### 一、一切都从事件循环开始
[[事件循环]]是这组材料的地基：同步代码先跑完 → 清空微任务队列 → 执行宏任务，所以「1 3 7 4 5 6 2」的输出顺序成立（[[豆包/wiki/summaries/编程与技术/JavaScript语言与基础]]）。
框架的更新调度直接建在上面：Vue 靠[[响应式系统]]依赖收集，把同一事件循环内的变更缓冲到微任务阶段统一刷新；React 靠虚拟 DOM + Diff + 批量更新。
[[setState]] 的「异步」也是同一原因——合成事件与生命周期中开启批量更新、多个 setState 被合并，而在 `setTimeout`/`Promise` 回调中脱离 React 控制，就表现为同步（[[豆包/wiki/summaries/编程与技术/Vue与React框架]]）。

### 二、两条范式：响应式依赖追踪 vs 虚拟 DOM + Diff
Vue 的核心是编译期与运行时的依赖追踪，[[Diff算法]]用双端比较（两端指针向中间收敛）加编译期 patchFlag 标记；更新粒度是组件级，精确更新受影响的 DOM。
React 的核心是[[虚拟DOM]] + 递归深度优先比较，靠 key 判断节点可否复用；[[Fiber架构]]把更新拆成小任务，按优先级拆分、暂停、恢复，代价是默认整棵子树重新渲染，需要 `React.memo` 之类手动优化。
第三条路线也被点到：Svelte 走编译时路线直接生成原生 DOM 操作、运行时无虚拟 DOM 比较；Angular 默认脏检查，可用 OnPush 策略减少检测。

### 三、React 没有「生命周期」是个错误说法
材料里最值得记住的一次纠错：类组件保留 `componentDidMount` 等完整钩子，Hooks 只是用 `useEffect`、`useLayoutEffect` 换个方式表达挂载/更新/卸载，其中 `useLayoutEffect` 在 DOM 更新后、浏览器绘制前同步执行。
同源问题还有 Vue 的 `ref`：它在 mounted 之后才拿到真实实例（此时 DOM 已创建并插入文档），父子组件引用同理。
跨层级共享用 `provide`/`inject`（[[依赖注入]]）而非逐层传 props；React 的数据流是单向的，子组件不能直接改父数据，所以流向可预测。

### 四、浏览器渲染：回流、重绘、rAF、缓存
渲染链路的几个关键区分：DOM Tree 含全部节点（含 `display:none`），RenderTree 只含需要显示的节点；`visibility:hidden` 仍在 RenderTree 并占位（[[豆包/wiki/summaries/编程与技术/浏览器、CSS与前端工程]]）。
[[回流与重绘]]的触发条件不同（尺寸/位置/增删可见元素触发回流，颜色背景阴影只触发重绘），回流必然伴随重绘；`requestAnimationFrame` 回调在每次重绘前执行，比 setTimeout 更平滑。
网络层是另一条线：强缓存由 Cache-Control / Expires 控制不发请求，[[协商缓存]]用 Last-Modified + If-Modified-Since 或 ETag + If-None-Match 校验，未变更返回 304。
[[同源策略]]里最容易混的一对概念是「跨域」与「跨站」：跨域看协议+域名+端口（管 AJAX/fetch），跨站只看根域名（管 Cookie 的 SameSite，防 CSRF）；所有跨站一定跨域，反之不成立。

### 五、手写题其实是同一批原理的复述
[[防抖]]（频繁触发只认最后一次）与[[节流]]（固定窗口内只执行一次）的差别落在「清掉旧定时器」还是「标志位锁住下限时间窗」。
`Promise.all` 的要点是用 `Promise.resolve()` 包装每个元素、计数、结果按下标写回保证顺序、任一 reject 立即 reject；JSONP 靠动态 `script` + 全局回调，只能 GET，现代已让位给 CORS。
[[深拷贝]]必须同时处理循环引用（WeakMap）与 Date/RegExp/Map/Set 等特殊类型；`typeof null === "object"` 是早期用低 16 位标记类型留下的兼容包袱；基本类型能调 String 方法靠的是临时包装对象。

### 六、工程化与性能：构建阶段 vs 运行阶段
构建工具的差异是「先打包后开发」与「原生 ESM 按需加载」：webpack 启动慢但可配置性强，Vite 开发态用浏览器原生 ESM、生产用 Rollup，启动与 HMR 更快（[[豆包/wiki/summaries/编程与技术/浏览器、CSS与前端工程]]）。
Tree Shaking 与 Code Splitting 都发生在构建阶段，Code Splitting 主要靠动态 `import()`、路由懒加载、多入口。
运行阶段的两类经典问题：长列表（约 1 万项）不要逐项绑事件，用[[事件委托]]挂到父元素，更极致用虚拟滚动；大规模游离 DOM 难回收，排查点是未移除的监听、全局变量缓存、闭包持有引用，核心是切断引用链。
另外两个常被追问的取舍：`for in` 遍历可枚举键名（含原型链，需 hasOwnProperty 过滤）而 `for of` 要求迭代器协议；快捷键模块「直接硬编码 vs [[依赖注入]]」取决于规模——少而稳定时硬编码性价比更高，依赖注入的价值在批量调整与统一禁用。
