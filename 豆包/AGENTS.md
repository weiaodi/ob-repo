# AGENTS.md（豆包 Wiki 工作域）

本文件约束在 `豆包/` 目录及子目录内工作的 AI agent。仓库根目录的 AGENTS.md 定义「学习教练」角色；本文件在其之上定义「知识库维护者」的操作规范。两处冲突时，在豆包/ 域内以本文件为准。

## 仓库是什么

豆包知识库 = 豆包 AI 对话历史的持久化 wiki（参考 Karpathy LLM Wiki 模式）。作用：让每次问答成为可复利的资产，而不是淹没在对话记录里。

```
豆包/
  raw/          # 原始资料层（60 文件 / 8 主题），不可变，事实来源
  wiki/
    summaries/  # 摘要页：每份 raw 一页
    concepts/   # 概念页：跨来源知识词条（209 个）
    syntheses/  # 综合页：跨来源专题综述（7 个）
  index.md      # 总索引，查询入口
  log.md        # append-only 操作日志
  AGENTS.md     # 本文件
  WIKI.md       # 参考手册（执行规范以本文件为准）
```

三层哲学：用户提供素材 → agent 读、提炼、串线、簿记 → wiki 是 agent 完成思考的「代码库」，index.md 是定位器，log.md 是时间线。

## 硬性规则（不可违反）

1. **raw/ 不可变**：不修改、不删除、不重命名 raw/ 下任何文件。raw 里的错别字、过时数字、AI 推断原样保留；加工层负责标注与澄清。
2. **正文零改写**：摘要/概念/综合页是对 raw 的提炼，不是改写。引用原文保留原措辞；不替用户写成品结论。
3. **来源纪律**：对话时点的数字、费率、政策一律标「（2026-10 对话时点，需核验）」；区分「AI 推断」「个人化结论」「对话原述」。
4. **隐私**：手机号、身份证、学号等个人标识**不得**写入 wiki 层（摘要/概念/综合页）；raw 层保持原样（它是私人档案）。
5. **概念命名唯一**：建概念页前先检查 `wiki/concepts/`，同名合并 `sources`，不重复建页；同义异名（如 刻奇/媚俗）归一后修正全库链接。
6. **wikilink 必须有效**：链接带路径消歧（`豆包/raw/编程与技术/其他杂项` 与 `豆包/raw/投资与理财/其他杂项` 是不同文件）；完成后校验 0 断链。

## Ingest 流程（写入新内容时）

新内容来源：用户丢进豆包/ 的新导出文件、粘贴的对话、手动新建的笔记。流程：

1. **清洗**：导出噪音——「嗨，我是你的新朋友豆包」「你好呀，欢迎回来…」「\*\*问题详情：\*\*」模板、`---` 消息分隔、不可见字符（U+2060）——全部移除；同一对话线程的追问合并到主问题下；标题从完整问题补全。
2. **归位**：清洗后的成品作为新文件放入 `raw/<主题>/`（主题已存在则归入对应文件夹，新主题新建文件夹），此时它成为不可变层。
3. **摘要**：在 `wiki/summaries/<主题>/<同名>.md` 生成摘要页。
4. **概念**：新概念建 `wiki/concepts/<名>.md`；概念已存在则只更新其「出现在」列表。
5. **综合**：若新内容与既有主题可串线，创建或更新 `wiki/syntheses/` 综合页。
6. **索引**：更新 `index.md`（新增页链接 + 一行导语）；概念页按主题分组计数同步。
7. **日志**：`log.md` 追加 `## [YYYY-MM-DD] ingest | 对象`，一行摘要说明做了哪些改动。
8. **校验**：全库 wikilink 有效性检查（当前基线 862 链接 0 失效，新改动后不得劣化）。

一次摄取一个新来源优先（保持可控）；内容量大时可多 agent 并行，但**概念名全局唯一**与**索引原子更新**必须由主 agent 收口。

## Query 流程（用户提问时）

先读 `index.md` 定位 → 相关摘要/概念/综合页 → 细节不够再进 raw。回答引用的内容给出 wiki 链接。若本次回答产生了值得沉淀的结论（对比、归因、梳理），按 Ingest 流程第 4~8 步归档回 wiki，并在 log.md 记 `query`。

## Lint 流程（定期 / 大改动后）

- 断链：扫描全部 `[[...]]`，目标必须存在（raw/wiki 相对 vault 根，`豆包/` 前缀）
- 孤儿页：无任何入链的摘要页或概念页（在 index 里至少应有一处）
- 概念重复：同义不同名、名字相似的概念页
- 漂移：raw 文件变化（应只有新增，不该有修改）时对应摘要页是否跟上了

## 页面格式速查

摘要页：
```markdown
---
type: summary
theme: <主题>
source: 豆包/raw/<主题>/<文件名>.md
created: YYYY-MM-DD
---
# <文件名>

> 三句以内导语

## 核心要点
- 3~8 条

## 涉及概念
[[概念]]、[[概念]]

## 值得回看的问答
- **<问题>**：<要点>
```

概念页：
```markdown
---
type: concept
created: YYYY-MM-DD
---
# <概念名>

一句话定义

## 出现在
- [[豆包/wiki/summaries/<主题>/<摘要页>|<主题> · <摘要页>]]
```

综合页：`type: synthesis`，40~80 行，含「框架 / 相关来源 / 延伸概念」，延伸概念名与摘要页严格同名。

## 与用户的协作约定

- 中文交流，术语保留英文
- 用户只负责：供素材、提问题、删内容（他有权删除本域内任何文件，包括 raw/）
- agent 负责：清洗、提炼、归并、簿记
- 涉及「删除、改名、整段改写」动作前先说明再执行；raw/ 的不可变是对 agent 的，不是对用户的
